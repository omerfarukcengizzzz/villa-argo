## Architecture

- `scripts/net.gd` (autoload `Net`): ENet host/join on port 7777 (max 1 client), `my_role()` (host = Jason), and registration of the input actions in code (keyboard + gamepad), not in `project.godot`.
- `scripts/game_state.gd` (autoload `GameState`): all host-authoritative state: flags, the twins' shared inventory, journal entries (each with `who`: both/jason/julia; in book 6, while `b6.playing_rick` is set, Julia's player plays Rick, so "julia" entries are Rick's). Only the host writes (`set_flag`, `give_item`, `add_journal`); writes are broadcast by RPC and a (re)joining client gets `send_snapshot`. Anything that must survive a level change or rejoin lives here, never in a level. `check(cond)` evaluates condition strings (`"flag"`, `"item:id"`, `"journal:id"`, `"flag=value"`, `"!..."`, joined with `" & "`) used by interactables and NPC lines. Story flags are namespaced by place (`argo.*`, `argo_door.*`).
- `scripts/main_menu.gd`: UI built in code. Host goes straight to the game; join waits for `connected_to_server`.
- `scripts/game.gd` (`Game`, scene `game.tscn`, `Game.current`): session root. Owns the twins (`Players` + `MultiplayerSpawner`), the loaded levels (nodes `Game/Level_<name>`; `level_for(role)`, `level` = this peer's twin's), the HUD (prompt, stacked toasts via host-only `say(text, who)`), the text box (`ask_text`), the choice list (`ask_choice`) and the journal UI. The client sends `_client_ready` after loading; the host replies with the state snapshot, the current level and only then spawns both twins (host = Jason, peer 1; client = Julia). `change_level(path, entry)` (host) moves both twins; `move_twin(role, path, entry)` moves one, splitting them (book 2). While split, the host keeps both occupied levels loaded (only Jason's visible) so it can validate everything; Julia's machine loads only hers. Each level sits at its `origin` so two can coexist; level positions (entries, respawn, stations) are local to the level. Lighting is per level (`Level.environment`, applied to this peer's camera).
- `scripts/level.gd` (`Level`): base for levels built in code (`_build` on every peer, `_host_setup` on the host, `entries` for spawn points, `fall_y`/`respawn_point` for falls, `set_night`, and `add_box`/`add_ramp`/`add_climb_wall`/`add_label`/`place` helpers). Levels live in `scenes/levels/` + `scripts/levels/`: `villa_argo` (start; also book 2's storm), `kilmore_cove`, `argo_underground`, `punt` (origin x 3000), `punt_corridors` (origin x 6000), `mirror_house` (origin x 9000), `argo_attic` (origin x 12000), `venice` (origin x 15000), `isle_of_masks` (origin x 18000), `school` (origin x 21000), `station` (origin x 24000), `garden` (origin x 27000) and `maze_town` (origin x 30000). `Level.sees(watcher, target, radius, fov)` is the host's vision check for patrolling watchers (cone plus line of sight; a `fov` of 360 means all round). Host checks on a twin's position should test real bounds (not just "z < something"): right after a level change the host can briefly still have the other twin at her old level's position. Level story hooks must not `await` past a level change (the level is unloaded); use `Game.say_later` for delayed messages. A level disconnects itself and its children from `GameState.changed` when it leaves the tree. Connect methods, not lambdas that use only local variables: such a lambda isn't bound to the level, so it isn't disconnected and fires on freed nodes.
- `scripts/interactable.gd` (`Interactable`) and `scripts/interactables/`: things a twin uses with interact (`Door`, `Pickup`, `Pushable`, `KeyLock`, `CodeEntry`, `Helm`, `FloorStone`, `LightSocket`, `Shutter`, `Mirror`, `SequenceButton`, `Dial`, `ChoicePoint` (`question_for` builds a question that changes with state), `Switch`, `Lever` (two positions, `stuck_when`), `Npc` (while the twins are apart, only the one talking hears the line), `SymbolButton`, `JournalNote`, `LevelExit`). `who` restricts which twin may use one, `requires` is a GameState condition, and `on_used` is a host-only story hook levels attach (journal entries, flags). The owning player shows a prompt for the nearest one; the press goes to the host, which validates role and distance, then `_host_interact` changes `GameState`; every peer redraws in `refresh()`. Interactables need stable node names (use `Level.place`) so RPCs resolve on both peers.
- `scripts/player.gd`: each peer is authority over its own player, simulates movement locally, and replicates `position` and `rotation:y` through a `MultiplayerSynchronizer` created in code. Only the owning peer gets a camera, input and interaction. `teleport` is a host-only RPC. Jason climbs inside `Climbable` zones (`scripts/climbable.gd`); a twin below the level's `fall_y` is put back at `respawn_point`, and one touching a `Hazard` (`scripts/hazard.gd`, e.g. the snakes; `active` makes it conditional) at the hazard's `respawn`.
- `scripts/vis.gd` (`Vis`): private per-twin visuals. Render layer 2 is Julia-only, layer 3 Jason-only; each camera culls the other twin's layer, and `Vis.make_private` also turns shadows off so nothing leaks. (Privacy is visual: the host's machine holds all state.)
- `scripts/journal_ui.gd` (`JournalUI`): Ulysses' journal overlay, showing only entries for this twin plus the shared inventory. Opening it blocks player input (`Game.input_blocked`).
- Scenes (`*.tscn`) are deliberately minimal (a root node plus script); most nodes are created in script.

## Constraints from GAME.md that shape all code

- **Engine:** Godot 4, GDScript. Keep scenes and scripts as plain text.
- **Networked from day one:** 2-player online co-op using Godot's high-level multiplayer API (ENet), one host and one client joining by IP (over Tailscale). Every interactive object (doors, levers, keys, puzzle pieces) must sync its state. The host is authoritative for puzzle/world state.
- **Asymmetric views:** each player sees only their own twin's view (Jason: explorer/climber; Julia: reads clues only she can see). Private per-player information is a core design tool, so visibility of puzzle info must be per-peer, not global.
- **Current scope:** Milestone 1 is a gray-box prototype with no art: Host/Join menu, capsule players with third-person cameras (keyboard + controller), synced movement, and one co-op puzzle room.
